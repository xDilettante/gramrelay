# Durable webhook lifecycle and incoming observations

Status: accepted for completed R4, 2026-11-16.

The optional tg-agent webhook feature shares the SDK ingress/parser/HTTP server. A lazy feed.webhook builder validates configuration and the verified bot identity before claiming SourceMode::Webhook. HTTP success follows append_webhook commit; identical stored duplicates remain successful after restart. Processing uses the separate durable consumer cursor. No webhook installation/removal, source reclaim after loss, or outbound Telegram action is implicit.

The parent future supervises HTTP, a lease heartbeat and a typed fatal-source signal. The heartbeat also runs during idle time and HTTP drain. It waits fairly for bounded DB admission and limits renewal waiting by its known lease expiry; enqueueing a renewal alone is insufficient evidence of ownership. The database remains authoritative: worker/generation/mode/expiry are checked after the write lock. Active requests use snapshots of the same generation. A lost source closes intake and cannot clear a newer owner's lease.

On normal stop, the shared server drains/joins its request lifetimes. Release then passes through the same fenced DB admission used by confirmation/cleanup. This waits behind a native append or renewal whose async waiter timed out. Only after this step does the parent release the process-local SDK guard. Native work can still commit after an HTTP timeout; a subsequent identical delivery deduplicates it. Native cleanup is awaited separately from the HTTP deadline. Dropping the whole future aborts owned HTTP tasks but cannot run async DB release, so its database lease remains bounded by expiry. Hosts should cancel the token and await the runtime before closing the journal.

One shared HTTP POST observation records a fixed status/reason and processing/commit decision. SDK tracing includes a local attempt ID and duration; metrics use only bounded result/status/reason labels and an aggregate active-pipeline gauge. Cancellation drops the gauge and produces a distinct category. The observer never receives route/header/body/ID values and holds no tracing enter guard across await. It makes no claim about peer receipt after handing the response to HTTP. The application owns subscriber/recorder, non-POST routing and its global panic hook.

Seven durable HTTP tests cover commit-before-ack, duplicate/conflict/quota/restart, cancelled native append fencing, idle renewal/foreign takeover, blocked renewal closure before expiry, lazy startup and whole-future drop. A native-worker test proves fair maintenance admission. The telemetry regression covers ten decisions/cancellations, static label values, private data exclusion and a balanced gauge. Existing J2 child-process crash tests remain part of the 214-test all-feature suite. Fresh durable lifecycle review found no actionable defect.
