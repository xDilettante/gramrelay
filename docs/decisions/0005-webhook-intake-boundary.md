# Shared authenticated webhook boundary

Status: accepted for the R4 transport foundation, 2026-11-16. Managed memory/durable source integrations are still open.

Ordinary bots should not depend on SQLite, while durable agent feeds need the same authentication/body/admission rules. WebhookIngress therefore calls a trusted WebhookSink and emits 200 only after its future reports processing or commit. It does not infer success from queue admission. The sink receives the original monotonic deadline so a future bounded worker queue cannot reset time already spent reading the body. Bot identity, process/database source ownership and deduplication belong to the managed entry points or an explicit low-level host integration.

Authenticate a single Telegram secret header before reading the body. WebhookSecret follows Telegram's character/length contract and has redacted Debug with no Display/Serialize. The existing maintained subtle implementation compares bytes; unequal header lengths need not take equal time. Reject repeated secret values rather than joining/picking them, and return the same 401 as an invalid credential. No URL/query authentication fallback is available. Media/framing checks and the real generated Update decoder follow authentication, and public responses contain only fixed codes.

Reserve a complete per-event byte budget before reading, bounded by the request count and aggregate reservation cap. This conservative reservation avoids accepting more simultaneous buffers than their worst-case allowance. Request Drop releases both quotas on validation errors, disconnects, timeouts and panics. A trusted sink panic becomes a fixed handler failure; SDK error responses never format its payload. The host's global panic hook remains host-owned. Shutdown first closes admission and then drains admitted request lifetimes; backend-owned jobs/native DB work require the managed layer's own fence/drain.

Axum supplies a method router for existing TLS servers. Its simple serve helper does not expose the connection controls needed here, so the managed HTTP/1 listener uses Hyper's maintained parser with a bounded JoinSet, header/parser bounds and connection lifetime. Shutdown closes the listener, requests graceful completion, then aborts and joins owned connections at its deadline. Dropping the serving future aborts its connection set and closes ingress. The managed plaintext listener defaults to loopback; an explicit trusted-proxy setting permits other addresses. TLS implementation, peer limits for an externally mounted router and remote setWebhook registration remain host responsibilities.

The foundation has 13 targeted tests: authentication before body reads, streamed overflow, original deadline propagation, backend completion, cancellation/panic quota release, slow connections, graceful/forced stop and whole-future abort. Fresh ingress/server review found no substantive defect; it identified a status wording mismatch, resolved by specifying 401 for repeated secrets. Defaults are bounded operational choices; comparative performance and load evidence remain Q2.
