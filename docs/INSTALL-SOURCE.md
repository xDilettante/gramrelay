# Подключение alpha из исходников

Используйте полный checkout Telegram Rust: основной crate, tg-agent, tg-mtproto
и каталог vendor поставляются вместе. Обычный проект может подключить нужные
компоненты без таблицы patch и без копирования внутренних настроек SDK:

```toml
[dependencies]
tg = { path = "../TelegramRust" }
tg-agent = { path = "../TelegramRust/tg-agent", features = ["mcp", "mtproto"] }
tg-mtproto = { path = "../TelegramRust/tg-mtproto" }
```

Каждый компонент подключается независимо. Обычному Bot API-приложению достаточно
tg. Прямые зависимости сохраняют проверенные исправления SDK и при подключении
библиотек из другого workspace. Для Git-зависимости укажите URL полного
репозитория и полный rev нужного коммита у каждого выбранного компонента.

Проверка собственного checkout, без настоящего Telegram:

```powershell
python tools/check_external.py
python tools/check_external.py --run
python tools/check_external.py --git --run
```

Скрипт создаёт отдельный временный Cargo workspace, проверяет исходники всех
трёх библиотек и пяти SDK, отсутствие дубликатов/chrono и запрет возврата к
реестровым версиям. При --run он выполняет in-memory Bot API, MCP через duplex
и MTProto через синтетический TL-обработчик с закрытием ресурсов. Тексты, токены
и сессии настоящих аккаунтов не используются. Результаты остаются в
target/external-consumer-evidence; временный проект удаляется после завершения
Cargo. Кэш сборки расположен отдельно в target/external-consumer. После
завершения проверки его можно удалить штатным
`cargo clean --target-dir target/external-consumer --profile dev`.

Git-проверка требует чистого коммита и использует локальный file URL с точным
rev. Первое получение Git checkout может обновить публичный индекс зависимостей;
сборка и исполнение затем работают с --locked --offline. --source позволяет
проверять перемещённый полный checkout. Внешние crates берутся из Cargo cache,
поэтому это не обещание полностью автономной поставки всех зависимостей.

Локальный ZIP-кандидат создаётся только из чистого коммита:

```powershell
python tools/source_bundle.py build
python tools/source_bundle.py check <archive.zip> --manifest <archive.manifest.json>
```

Файлы появляются в target/dist. Манифест содержит полный commit, версию,
SHA-256 архива и точный список файлов с размерами, правами и SHA-256. Повторный
экспорт одного коммита теми же Git/Python должен дать одинаковые байты. Экспорт
сверяет их с Git-объектами и отказывается от изменённого через export-атрибуты
содержимого. В архив входят все отслеживаемые исходники, Cargo.lock, настройки,
тесты, документация и лицензии SDK; кэши и .git не входят.

Пять оригинальных release-архивов SDK включены в vendor/upstream (менее 1 МиБ
вместе). Верификаторы сначала используют их и проверяют закреплённые SHA-256
до разбора. Поэтому проверка патчей не требует заранее скачанных оригинальных
SDK в Cargo cache и не обращается к сети. Обычные runtime-зависимости по-прежнему
предоставляет Cargo cache. Повреждённый включённый архив вызывает отказ.

Обычная check только проверяет данные. Она ограничивает размер и число записей,
проверяет локальные заголовки и фактический конец сжатых потоков, отвергает
опасные/повторяющиеся пути, ссылки и коллизии имён Windows. Это ограниченный
профиль Git ZIP, а не универсальный распаковщик. Контрольные суммы подтверждают
целостность; подлинность автора они не доказывают.

Для собственного доверенного кандидата доступна отдельная проверка с исполнением:

```powershell
python tools/source_bundle.py check <archive.zip> --manifest <archive.manifest.json> --consumer
```

Она распаковывает уже проверенные байты в новый временный каталог, запускает
оттуда проверку пяти SDK и внешний Rust-пример. Cargo исполняет код и build scripts:
используйте --consumer только для кандидата, которому доверяете. Проверка не
берёт исходники или настройки из первоначального checkout; обычные сторонние
зависимости доступны через Cargo cache. После завершения временное дерево
удаляется, доказательства остаются в target/source-consumer-evidence. Кэш
сборки очищается командой
`cargo clean --target-dir target/source-consumer --profile dev`.

Это подготовка alpha из исходников. Реестровые .crate-кандидаты остаются в Q3.
Для реестра нужны отдельные идентификаторы
исправленных SDK либо проверенные upstream-релизы, окончательные имена,
метаданные, а также проверка нормализованных архивов. Собственный код остаётся
[закрытым](PRIVATE-DISTRIBUTION.md); публичная лицензия ему не предоставлена.
publish=false и зависимости без version предотвращают случайную упаковку,
которая потеряет исправления. Публикация требует отдельного поручения.
