# In-memory test kit (T1)

Feature test-kit exposes tg::test_kit without bot-runtime, tracing, metrics or socket dependencies of its own. MockTransport installs an optional in-memory execution path on BotBuilder, using reqwest's real request serialization/body streams and Response conversion into the production decoder. A mock never falls back to network, including unexpected methods or exhausted scripts. MockTransport.bot() uses a fixed synthetic token; bot_builder() permits normal trusted limit/deadline settings.

MockTransport::new accepts ordered Step fixtures. Step matches a sealed API method name (or download), then responds with MockResponse or injects a transport failure, an indefinitely pending response after dispatch, or a partial upload failure after a chosen byte count. Delays before response headers and between response chunks, malformed JSON, refusal envelopes, response-body interruption and out-of-order update arrays use the same response machinery. No task is spawned. Cancellation consumes the claimed step, retains the bounded request prefix and drops the remaining stream; later work cannot replay a cancelled write.

RecordedRequest exposes method, HTTP verb, content type, body bytes, upload_complete, and decode<M: Method>() for JSON requests. Decode verifies the method as well as strict generated request parameters. No credential URL, authorization headers or file path is recorded by transport metadata. Multipart body contents intentionally contain the caller's test data, including synthetic filenames; all Debug implementations omit fixture/record bodies. Test data is caller-controlled and must be synthetic. Explicit body()/decode access is the inspection boundary.

Default limits: 256 script steps/recorded requests and 1 MiB total recorded body bytes, with a separate equal bound for all queued response bytes. with_limits can change these trusted settings; positive finite limits are checked. No mutex is held across await. Claiming a step and reserving a record is atomic; parallel calls consume steps in execution order. History is bounded and immutable apart from upload progress; snapshots do not remove records while requests are active. Unexpected method/exhaustion/capture capacity fail closed with safe errors; assert_finished reports unused steps without exposing fixtures. Each Bot still enforces the real semaphore, preparation/file caps and total deadline. Script errors are returned to the caller, never panics or detached failures.

Acceptance: public examples run offline without DNS/listeners, typed request recording, actual multipart serialization and partial upload, 429 with retry_after, ambiguous writes without replay, reads with opt-in retry, cancellation/deadline/capacity release, bounded record/fixture budgets, shared chunked response caps/decode errors, method mismatch and script exhaustion, handler dispatch with reordered updates. All default/client-only/test-kit/combined feature builds and regression checks pass. Localhost wire tests remain the separate real HTTP integration boundary.
