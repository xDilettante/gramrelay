# Durable operation journal (J1)

tg-agent is a separate workspace package. Its SQLite journal accepts host-provided profile/principal identifiers; it is storage, not an authorization grant. The shared executor in A1 must check current grants and scopes before prepare, reads and cached-result access. No raw Bot API bypass is added here.

The operation key is (profile, operation_id). A row permanently binds its principal, action and SHA-256 of canonical JSON parameters. Bound payload depth/node/byte sizes before hashing; recursively sort object keys, preserve arrays, numeric representations and explicit null. Raw parameters/files/tokens are never stored. Different payload/action is Conflict; different principal is Denied and cannot read the row. Lookup for an incorrect principal returns no row. Diagnostics and Debug omit payloads, results, database paths and identifiers.

States: prepared, in_flight, succeeded, rejected, unknown. prepare reserves a key and grants one process instance a versioned prepared lease; duplicate callers receive a snapshot, never another lease. begin atomically checks profile/key, principal, worker, revision, prepared state and unexpired lease/lifetime before committing in_flight and returning an opaque flight lease. Only then may the caller send. complete compares worker/version/state atomically. A valid late confirmation may finish an unchanged in-flight row; after recovery fences its version the old worker cannot finish. A known NotSent releases the row back to prepared with a new revision; explicit refusal becomes rejected; ambiguous failure becomes unknown. Succeeded is terminal and is read from cache, including when the result body is no longer retained. No unknown/rejected/succeeded row returns an executable lease.

SQLite transactions use BEGIN IMMEDIATE, a unique key and version comparisons. Use WAL and synchronous=FULL; confirm PRAGMA values, version the schema, and reject foreign/newer schemas before mutation. One connection per Journal instance is protected by a mutex inside bounded spawn_blocking work. Permits remain with that work after an async caller cancels. No async runtime thread performs database I/O and no database mutex crosses await. Database paths are trusted absolute local paths in a caller-protected directory; memory/URI databases are excluded. New Unix database files use 0600. Windows inherits the directory ACL. No credentials are written here. Operators must protect the directory, database/WAL/backups and local disk. SQLite is not a transaction with Telegram.

Recovery only changes in_flight rows whose persisted lease expired, marking unknown and advancing the revision. Startup never resets other active executors. An expired prepared lease may be claimed again because no network attempt began. Lease expiry never grants permission to resend an in-flight action. Clock jumps may conservatively create unknown or delay recovery, but must not permit a second send. A bounded recovery operation and per-key access support restart without detached work.

Default limits: 100,000 retained operation keys, 16 pending database jobs per instance, 60-second lease, 7-day result/lifetime window, 64 KiB canonical payload, 64-level depth, 8,192 JSON nodes, 64 KiB per stored result. All configurable host limits are positive and overflow-checked. Result TTL discards cached bodies and fences expired prepared records; key/hash/owner/state tombstones remain. Capacity exhaustion rejects new reservations instead of silently deleting keys. There is no automatic purge-key API. Explicit operator namespace/archive changes end old guarantees and belong in operations documentation. An oversized or disabled result cache still records succeeded with an explicit result-availability category; it must not erase a known success or enable replay.

Receipts/failure data are minimal structured values. They may contain private data deliberately supplied by the host; retain_results(false) disables success bodies, while keys/state remain durable. No raw error source/remote description is persisted or exposed. Failed journal commits after a network action must be treated as ambiguous by A1, never NotSent. Cancellation of a database future may leave its transaction committed; callers query the same key rather than inventing a new one.

Acceptance: concurrent independent connections/processes yield one executable claim; payload/order/owner checks, cross-profile isolation, stale lease fencing, known NotSent, rejected/unknown/success replay, restart before/after attempt/result, active-owner preservation, TTL/tombstone/capacity/result limits, database task cancellation/capacity, foreign/corrupt schema and diagnostic privacy. Actual child-process termination tests cover the send/commit gap without live Telegram calls. A1 adds end-to-end authorized execution; J1 alone does not claim exactly-once delivery.
